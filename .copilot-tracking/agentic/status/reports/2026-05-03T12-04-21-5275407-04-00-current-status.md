## Current State

The Godot prototype now starts with the returned Mission 1 concept image,
advances into Mission 1, advances after victory to the returned Mission 2
relay-yard image, and then starts Mission 2. Mission 2 is now represented in the
C# core with relay and fuel-cache objectives, Engineer and Sapper unit roles,
and mission metadata that drives Godot HUD text.

The art pass now uses returned terrain, unit, and UI sheets as extractor inputs
instead of draw-time crop sources. `Wargame.AssetTools extract-art` creates
`art_terrain.png`, `art_units.png`, and `art_ui_icons.png`; the Godot runtime
prefers these extracted atlases and keeps deterministic generated sheets as
fallbacks.

The first-act campaign mode now has a planning document for Missions 1-10 that
defines the linear mission select, briefing, battle, debrief, score, save,
unlock, replay, and art-ID expectations. The existing art-handoff tree now has
`game/WargamePrototype/assets/art-handoff/requests/10-missions-01-10-imagery-thread`
as the monitored folder for cutscenes, portraits, unit sprites, terrain, props,
UX overlays, Sable/Meridian style exploration, the Mission 8 blackout kit, and
the Mission 10 refinery finale kit.

The Godot prototype now also has the playable first-act campaign loop in code.
`Wargame.Core` exposes a deterministic campaign mission catalog and factory for
Missions 1-10, and the Godot controller advances through mission intro,
playable battle, debrief, next mission, and campaign-complete screens. Mission 1
victory no longer resets the same mission.

## Challenges And Risks

* Mission 2 wait-to-capture objectives are deterministic, but may need stronger
  controller prompts, visual affordances, or different pacing after playtest.
* Full animated cutscene sequencing still belongs to a later pass. The current
  flow uses returned concept images as static cutscene screens.
* Corner-keyed transparency is good enough for the current source sheets, but
  true transparent PNG reruns will be cleaner and reduce edge halo risk.
* Terrain variants are currently rotated or mirrored from the first returned
  concept sheet. The new prompt asks for purpose-built tileable variants.
* Automated asset-load, dimension, and nonblank assertions would catch missing
  or blank runtime art more directly than headless startup alone.
* Sidebar-covered 1280x800 evidence for the arena HUD remains pending and now
  should include the Mission 2 markers.
* Missions 3-10 are playable deterministic fixtures, but they still need authored
  mission tuning, bespoke art promotion, and 1280x800 visual evidence.
* The new campaign screens are static text and concept-image screens. Animated
  cutscene sequencing remains later work.
